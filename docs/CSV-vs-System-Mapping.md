# การเทียบข้อมูลไฟล์ CSV กับระบบ

**อัปเดต:** 2026-03-21

เอกสารนี้เทียบโครงสร้างและความสัมพันธ์ระหว่างไฟล์ CSV ที่มี กับโครงสร้างข้อมูลในระบบ (Prisma / หน้าแจ้งปัญหา)  
หน้าแจ้งปัญหา (`/report`) เรียงการ์ด: ผู้แจ้ง → สถานที่ → รายละเอียดปัญหา → รูปภาพประกอบ และดึงรายการ Site ผ่าน API `GET /sites` (Public).  
บทบาทผู้ใช้ในระบบ: ADMIN, STAFF, USER, SUPERVISOR (หัวหน้างาน — มอบหมายงานได้); ดู RBAC ที่ `backend/docs/RBAC-Setup.md`.

---

## 1. area_project.csv → ตาราง `Site` (พื้นที่ในโครงการ)

| CSV (area_project.csv) | ระบบ (Site) | หมายเหตุ |
|------------------------|-------------|----------|
| จังหวัด | province | ตรงกัน |
| อำเภอ | district | ตรงกัน |
| หน่วยงาน | agency | ตรงกัน |

**ความต่างของข้อมูล:**
- ใน CSV มีหลายแถวที่คอลัมน์ **จังหวัด** ว่าง (มีแค่ อำเภอ + หน่วยงาน เช่น เทพา, นาหม่อม, สะเดา) — ระบบจะข้ามแถวที่จังหวัดว่าง เพราะ Site ต้องมีครบ 3 ฟิลด์
- จาก **ข้อมูลการแจ้งซ่อม.csv** งานแจ้งซ่อมใช้ค่าคู่ เช่น **สงขลา + สะบ้าย้อย/นาทวี/เทพา/จะนะ + สถานีตำรวจภูธร หรือ ที่ว่าการอำเภอ** แต่ใน area_project.csv แถวที่ระบุจังหวัดสงขลาไว้มีแค่ **เมืองสงขลา + สถานีตำรวจภูธร**
- **ข้อเสนอ:** ถ้าต้องการให้ dropdown ในหน้าแจ้งปัญหามีตัวเลือกตรงกับงานจริง ควรเพิ่มรายการ (จังหวัด, อำเภอ, หน่วยงาน) ที่ปรากฏในงานแจ้งซ่อมลงใน area_project หรือให้ seed จาก CSV นำเฉพาะแถวที่ครบทั้ง 3 คอลัมน์ และมีอีกชุดจาก “ข้อมูลการแจ้งซ่อม” เป็นรายการ Site เพิ่มเติม

---

## 2. ผู้แจ้ง.csv → ตาราง `User` (role = USER, ผู้แจ้งซ่อม)

| CSV (ผู้แจ้ง.csv) | ระบบ (User) | หมายเหตุ |
|------------------|-------------|----------|
| IDแจ้ง | - | ใช้สร้าง username ถ้าไม่มี Email |
| ชื่อ-สกุล | name | ตรงกัน |
| ตำแหน่ง | position | ตรงกัน |
| Email | email, username (ส่วนก่อน @) | ตรงกัน |
| เบอร์โทร | phone | ตรงกัน |
| รูปภาพ | image | path ใน CSV เก็บเป็น path ได้ |

โครงสร้างตรงกับที่ระบบและ seed จาก Excel (ชีท “ผู้แจ้งแก้ไข”) ใช้อยู่

---

## 3. ผู้แก้ไข.csv → ตาราง `User` (role = STAFF) + ใช้ใน Area

| CSV (ผู้แก้ไข.csv) | ระบบ (User) | หมายเหตุ |
|--------------------|-------------|----------|
| ID | - | ไม่ได้ใช้ใน schema |
| ชื่อ-สกุล ผู้แก้ไข | name | ตรงกัน (ต้องใช้ชื่อเดียวกันใน Area) |
| ตำแหน่ง | position | ตรงกัน |
| Email | email, username | ตรงกัน |
| เบอร์โทร (มีเว้นวรรคท้าย) | phone | ตรงกัน |
| รูปภาพ | image | path ได้ |

โครงสร้างตรงกับชีท “ผู้แก้ไข” ใน Excel ที่ seed ใช้

---

## 4. พื้นที่รับผิดชอบ.csv → ตาราง `Area`

| CSV | ระบบ (Area) | หมายเหตุ |
|-----|-------------|----------|
| ลำดับ | - | ไม่เก็บใน Area |
| **อำเภอ** (ใน CSV) | district | ในไฟล์นี้คอลัมน์นี้เป็นชื่อ **จังหวัด** (สงขลา, ยะลา, นราธิวาส, ปัตตานี, สตูล) ไม่ใช่ชื่ออำเภอ |
| Site Engineer | - | ใช้ชื่อไปหา User (staff) → staffId |
| เบอร์ติดต่อ | - | เก็บใน User.phone ผ่าน Staff แล้ว |

**ความต่างสำคัญ:**
- ในระบบ Prisma ค่า `Area.district` หมายถึง “อำเภอ” แต่ใน CSV คอลัมน์ “อำเภอ” เป็นระดับ **จังหวัด**
- **ทางเลือก:** (ก) ใช้ค่าจาก CSV นี้เป็น **จังหวัด** แล้วในระบบเก็บเป็น `district` = ชื่อจังหวัด (ระดับจังหวัดต่อ 1 Area), หรือ (ข) ปรับ schema แยก province/region ถ้าอนาคตจะรองรับทั้งจังหวัดและอำเภอ
- คอลัมน์ **Site Engineer** บางแถวมีหลายคน (หลายบรรทัดในเซลล์) — ต้องแยกบรรทัดแล้วสร้าง 1 Area ต่อ 1 คน ต่อ 1 จังหวัด

## 5. ข้อมูลการแจ้งซ่อม.csv → ตาราง `Job`

| CSV | ระบบ (Job) | หมายเหตุ |
|-----|------------|----------|
| เลขที่ใบแจ้งซ่อม | ticketNo | ตรงกัน |
| วัน เวลาที่แจ้งซ่อม Auto | reportDate | ต้องแปลงรูปแบบวันที่ (ใน CSV เป็นข้อความ เช่น 10/9/2024 11:34:18) |
| จังหวัด | province | ตรงกัน |
| อำเภอ | district | ตรงกัน |
| สถานที่ | location | ตรงกัน |
| ชื่อ-สกุล | reporterName | ตรงกัน (หรือผูก reporterId ถ้ามี User) |
| เบอร์โทร | reporterPhone | ตรงกัน |
| Email ผู้แจ้ง | reporterEmail | ตรงกัน |
| ข้อขัดข้อง | description | ตรงกัน |
| 1.–3. รูปภาพข้อขัดข้อง | images | ใน CSV เป็น path ระบบรองรับ Json (path หรือ base64 ก็ได้) |
| สถานะ | status | แมป "แล้วเสร็จ" → RESOLVED, อื่นๆ ตามกฎใน seed |
| เลขที่ใบแก้ไข | fixTicketNo | ตรงกัน |
| วัน เวลาที่แก้ไข Auto | fixDate | แปลงรูปแบบวันที่ |
| ผู้แก้ไข | - | ใช้ชื่อไปหา User (staff) → assignedToId |
| เบอร์โทรผู้แก้ไข | fixerPhone | ตรงกัน |
| Email ผู้แก้ไข | fixerEmail | ตรงกัน |
| ส่วนที่ขัดข้อง | brokenPart | ตรงกัน |
| สาเหตุ | cause | ตรงกัน |
| วิธีแก้ไข | fixMethod | ตรงกัน |
| Serial Number อุปกรณ์เดิม/ใหม่ | oldSerialNumber, newSerialNumber | ตรงกัน |
| 1.–3. รูปการแก้ไข | fixImages | Json (path หรือ base64) |
| หมายเหตุการแก้ไข | fixNote | ตรงกัน |
| สถานะระบบ | systemStatus | ตรงกัน |

- คั่นฟิลด์ใน CSV: **Tab** (\t)
- รูปภาพใน CSV เป็น path (เช่น `ระบบแจ้งซ่อม CCTV_Images/...`) ระบบเก็บเป็น JSON ได้ ไม่จำเป็นต้องอัปโหลดไฟล์จริงตอน seed

## สรุปการเทียบและสิ่งที่ต้องทำ

1. **Site (พื้นที่ในโครงการ)**  
   - ใช้ **area_project.csv** ได้ แต่เฉพาะแถวที่กรอก **จังหวัด, อำเภอ, หน่วยงาน** ครบ  
   - ควรเพิ่มรายการ (จังหวัด, อำเภอ, หน่วยงาน) ที่โผล่ใน **ข้อมูลการแจ้งซ่อม.csv** ด้วย เพื่อให้ dropdown ในหน้าแจ้งปัญห�อดคล้องกับงานจริง

2. **User (ผู้แจ้ง)**  
   - **ผู้แจ้ง.csv** เทียบกับระบบได้ตรง ใช้ seed เป็น User role=USER ได้

3. **User (ผู้แก้ไข)**  
   - **ผู้แก้ไข.csv** เทียบกับระบบได้ตรง ใช้ seed เป็น User role=STAFF ได้

4. **Area (พื้นที่รับผิดชอบ)**  
   - ใช้ **พื้นที่รับผิดชอบ.csv** ได้ แต่ต้องยอมรับว่าใน CSV คอลัมน์ “อำเภอ” คือ **จังหวัด**  
   - แนะนำ: เก็บใน `Area.district` เป็นชื่อจังหวัด (หรือเพิ่มฟิลด์ province ในอนาคต) และแยกบรรทัดใน Site Engineer เป็น 1 Area ต่อ 1 คนต่อ 1 จังหวัด

5. **Job (การแจ้งซ่อม)**  
   - **ข้อมูลการแจ้งซ่อม.csv** แมปกับฟิลด์ Job ได้ครบ ต้องจัดการเฉพาะ: แปลงวันที่ และแมปชื่อ “ผู้แก้ไข” เป็น assignedToId จากตาราง User

ถ้าต้องการให้ระบบ “เทียบ” แบบอัตโนมัติ แนะนำให้มีสคริปต์ **seed-from-csv** ที่อ่านจาก CSV เหล่านี้และแมปตามตารางด้านบน

สคริปต์ `backend/scripts/seed-from-csv.ts` ทำแล้วดังนี้:
- **Site:** สร้างจาก area_project แล้วเพิ่มรายการ (จังหวัด, อำเภอ, สถานที่) ที่ไม่ซ้ำจาก ข้อมูลการแจ้งซ่อม.csv
- **การแมปชื่อ Staff:** ใช้ `getStaffId()` รองรับคำนำหน้าและชื่อคล้าย สำหรับ Area และ Job (assignedToId)
- **Area:** กันการสร้างซ้ำด้วยคู่ (จังหวัด, staffId)
